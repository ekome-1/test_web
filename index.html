このMVPが見るもの

  • malloc / calloc / realloc / strdup系の代入
  • if/elseの両側で解放されるかを確認（片側だけなら候補を維持）
  • q = pや別名チェーン経由のfree
  • 同じファイル内で引数をfreeする独自解放関数の呼び出し
  • 同じ関数ブロック内のreturn pointerによる所有権移譲
  • コメントと文字列リテラルを除外したCトークン

結果の読み方

これは軽量な静的ヒューリスティックです。ループ内の解放だけでは解放済みと判定せず、構造体メンバー・ポインタ演算・キャスト・関数ポインタ・goto/switch・プリプロセッサ展開や別ファイルの解放関数は追跡しません。複雑なC構文では誤検出・見逃しがあり得ます。「候補なし」は安全の保証ではありません。重要なコードはClang Static AnalyzerやAddressSanitizerでも確認してください。
